{% raw %}## What you will learn

* Identify the main components of a functional project specification and explain the purpose of each section
* Develop a project idea into a full, detailed specification

## Do Now

### Detailed Specifications

* Ask students to take out their feature lists and flow charts from [Lesson 8.2]({% endraw %}{{ '/docs/lesson_plans/units/8_unit/02_lesson/lesson.html' | relative_url }}{% raw %}).
* You will be using these to develop a more detailed specification and plan for your project today.
* Read through them and make sure you have included all the main points.

## Check your understanding

Pick an answer for each question. You can try again until you get it right.

<div class="quiz" markdown="1">

<div class="q" data-answer="a" markdown="1">
**1. What is the purpose of a project specification?**

- To describe in detail how the project will work so you can build it from a clear plan
- To replace the code
- To list only the project's name
- To record the final grade

<p class="why">A spec spells out the details so you don't have to guess while coding.</p>
</div>

<div class="q" data-answer="c" markdown="1">
**2. Why should your spec be built from your feature list and flow chart?**

- Those documents are no longer needed
- Because specs should not include features
- They hold the main points of the project, which the spec expands into detail
- So you can skip the schedule

<p class="why">The spec develops the earlier planning into specifics.</p>
</div>

<div class="q" data-answer="b" markdown="1">
**3. What is a likely result of leaving steps or requirements out of the spec?**

- The project becomes simpler automatically
- Planning is harder and you may need major changes or cuts later
- Nothing, since specs are optional
- The code writes itself

<p class="why">Missing details make the plan unreliable, which causes surprises during development.</p>
</div>
